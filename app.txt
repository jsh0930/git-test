######### 사용방법 #########

<초기 설정>
1. 작업 폴더 생성
2. 작업 폴더 Shift + 우클릭
3. 파워쉘 열기
4.  $ git config --global user.email wjdtjr6446@gmail.com
    $ git config --global user.name jsh0930

<add, commit> 수정한 파일만 기록할때
1. vscode로 작업 폴더 열기 + 새 터미널 생성
2. 터미널에 
    $ git init
    // 깃이 작업폴더를 감지
3. 작업 폴더 내 파일 생성하고 작업 및 저장
4. 터미널에
    $ git add 파일명
    // 저장 장바구니에 담아두기
    $ git commit -m '메모'
    // 저장 장바구니 최종 결제
5. 추가로 작업을 더 했다면 다시 터미널에
    $ git add 파일명
    $ git commit -m '메모'

6. 여러 파일을 스테이징 할때
    $ git add 파일명1 파일명2
7. 모든 파일을 스테이징 할때
    $ git add .
8. 상태창 열기 (어떤 파일을 스테이징 했는지, 수정 했는지)
    $ git status
9. commit 내역 조회
    $ git log --all --oneline



<diff> 최근 commit vs 현재파일 차이점 보여줌
1.  $ git diff
    # j,k로 스크롤, q로 나가기
    # 근데 스페이스바 같은것도 인식해서 조금 버그같은게 있음
2.  $ git difftool
    # h, j, k, l키가 방향키, 종료는 :q 또는 :qa
    # Vim 에디터로 동작하고
    # 이게 비주얼적으로 조금더 좋음
3. 현재 파일 vs 특정 커밋 비교
    $ git difftool 커밋아이디
    # 커밋 아이디란 $ git log --all --oneline 이거 했을때 왼쪽의 노란 아이디
4. 특정 커밋 vs 특정 커밋
    $ git difftool 커밋아이디1 커밋아이디2
    # 익스텐션에 git graph 있는데 잘 쓰면 편함



<branch> 프로젝트 복사본(커밋의 복사본)
1.  $ git branch 브랜치명
    # 브랜치 생성
2.  $ git switch 브랜치명
    # 프랜치로 이동 (브랜치가 뻗어 나온 노드 이름은 main임)
3. 만약 app.txt 라는 파일에서 작성 -> 커밋 -> 작성 -> 커밋 하다가
4. 특정 노드에서(커밋한 구간에서) branch를 하고 새로운 파일을 만들고 커밋 -> 작성 -> 커밋 하고
5. 다시 브랜치가 뻗어나온 노드인 main으로 돌아가면 새로 만들었던 파일은 없어짐
6. 왜냐하면 그 파일은 branch한(예: coupon이라는) 노드에서 생성했기 때문에
7. 그래프로 쭉 볼려면
    $ git log --oneline --all --graph



<merge> 브랜치 합치기
1. main으로 브랜치 합치기
    # 우선 기준이 되는 브랜치로 이동 (main)
2.  $ git merge 합칠브랜치명
