######### 사용방법 #########

<초기 설정>
1. 작업 폴더 생성
2. 작업 폴더 Shift + 우클릭
3. 파워쉘 열기
4.  $ git config --global user.email wjdtjr6446@gmail.com
    $ git config --global user.name jsh0930

<add, commit> 수정한 파일만 기록할때
1. vscode로 작업 폴더 열기 + 새 터미널 생성
2. 터미널에 
    $ git init
    // 깃이 작업폴더를 감지
3. 작업 폴더 내 파일 생성하고 작업 및 저장
4. 터미널에
    $ git add 파일명
    // 저장 장바구니에 담아두기
    $ git commit -m '메모'
    // 저장 장바구니 최종 결제
5. 추가로 작업을 더 했다면 다시 터미널에
    $ git add 파일명
    $ git commit -m '메모'
6. Git 기록 완전 삭제할때
    $ rm -r -force .git

        ######################################################################################
            작업폴더                       staging areare                   pository(저장소)
        ----------------                 ----------------                 ----------------
        |              |                 |              |                 |              |
        |   작업물 1    |     git add     |              |   git commit    |              |  
        |   작업물 2    |  ------------>  |    작업물 2   |  ------------>  |    작업물 2   |
        |   작업물 3    |                 |              |                 |              |
        |              |                 |              |                 |              |
        ----------------                 ----------------                 ---------------- 

        작업물을 고르는 행위(add)를 staging 한다 라고 표현함
        ######################################################################################

7. 여러 파일을 스테이징 할때
    $ git add 파일명1 파일명2
8. 모든 파일을 스테이징 할때
    $ git add .
9. 상태창 열기 (어떤 파일을 스테이징 했는지, 수정 했는지)
    $ git status
10. commit 내역 조회
    $ git log   # 버전확인
    $ git log --all  --oneline  # 한줄 이력확인
11. 특정 파일 add 취소
    $ git restore --staged 파일명
12. 모든 파일 add 취소
    $ git restore --staged .
13. 방금 한 커밋 취소 (코드 보존)
    $ git reset --soft HEAD~1
14. 방금 한 커밋+add 취소
    $ git reset --mixed HEAD~1
15. 방금 한 커밋+코드 완전 삭제
    $ git reset --hard HEAD~1
16. 완전 과거로 타임머신
    $ git reset --hard [커밋ID]
17. 안전하게 과거 취소 (협업용)
    $ git revert [커밋ID]   # 변경 사항을 정반대로 뒤집는 '취소 전용 커밋'을 새로 생성




<diff> 최근 commit vs 현재파일 차이점 보여줌
1.  $ git diff
    # j,k로 스크롤, q로 나가기
    # 근데 스페이스바 같은것도 인식해서 조금 버그같은게 있음
2.  $ git difftool
    # h, j, k, l키가 방향키, 종료는 :q 또는 :qa
    # Vim 에디터로 동작하고
    # 이게 비주얼적으로 조금더 좋음
3. 현재 파일 vs 특정 커밋 비교
    $ git difftool 커밋아이디
    # 커밋 아이디란 $ git log --all --oneline 이거 했을때 왼쪽의 노란 아이디
4. 특정 커밋 vs 특정 커밋
    $ git difftool 커밋아이디1 커밋아이디2
    # 익스텐션에 git graph 있는데 잘 쓰면 편함



<branch> 프로젝트 복사본(커밋의 복사본)
1.  $ git branch 브랜치명
    # 브랜치 생성
2. 브랜치 목록 보기
    $ git branch
3.  $ git switch 브랜치명
    # 프랜치로 이동 (브랜치가 뻗어 나온 노드 이름은 main임)
4. 만약 app.txt 라는 파일에서 작성 -> 커밋 -> 작성 -> 커밋 하다가
5. 특정 노드에서(커밋한 구간에서) branch를 하고 새로운 파일을 만들고 커밋 -> 작성 -> 커밋 하고
6. 다시 브랜치가 뻗어나온 노드인 main으로 돌아가면 새로 만들었던 파일은 없어짐
7. 왜냐하면 그 파일은 branch한(예: coupon이라는) 노드에서 생성했기 때문에
8. 그래프로 쭉 볼려면
    $ git log --oneline --all --graph
9. 브랜치 삭제
    $ git branch -d 브랜치명

    # 이전 브랜치에 있던걸로 할지 수정하면됨
4. 수정 끝났으면
    $ git add .
    $ git commit '커밋명'



<Git 구성> 끝내기
1. git init을 실행한 순간 해당 폴더에 .git이라는 숨김 폴더가 생성
2. 폴더를 삭제하지 않는 한 Git은 백그라운드에서 영구적으로 파일의 상태를 감지
3. 따라서 git commit까지 완료하여 변경 사항을 안전하게 기록했다면,
    단순히 VSCode와 터미널 창을 닫는 것만으로 깔끔하게 작업이 끝납니다.



<Git 구성> 다시 불러오기
1. 앞서 설명했든 숨김 폴더가 있고 지속적으로 파일을 감지하기 때문에
2. 다시 불러오기를 할 필요가 없음
3. VScode로 해당 작업 폴더를 열기만 하면됨



<GitHub 연동> 원격 저장소 연동
1. GitHub로 올리거나 가져올 때 사용
2. GitHub 주소 연결
    $ git remote add origin 주소
3. 깃허브에 올리기
    $ git push origin 브랜치명
4. 폴더 통째로 다운로드
    $ git clone 주소
5. 업데이트 가져오기
    $ git pull origin 브랜치명
